# 业务调研记录 · 需求拆解留痕

> **文档性质**：本记录把「企业信息化场景里反复出现的典型业务痛点」结构化为可落地的前端需求。
> 方法是**桌面调研 + 业务角色视角梳理**（依据公开的 HR / 财务 / 行政审批流程，以及中后台系统的通用使用经验），
> **不是**某家企业的现场访谈纪要 —— 记录中的「调研对象」指业务角色 / 岗位，不是具体个人。
>
> **每条记录的结构**：业务角色 → 当前做法 → 痛点 → 需求拆解 → 落地需求卡 → 验收标准。
> 目的是留痕一件事：**一句话的业务抱怨，是怎么变成一张带验收标准的需求卡的。**

## R-001 · 人事入职资料收集

- **业务角色**：HR（入职流程经办岗）
- **当前做法**：Excel 模板 + 微信/邮件收资料，HR 人工核对后再转交各部门

| # | 痛点（业务原话） | 需求拆解（可验收的表述） | 落地 |
| --- | --- | --- | --- |
| 1 | 「一张表 30 多个字段铺满屏，填错要来回返工三次」 | 长表单按业务阶段切分，每步只问该步该问的字段；分步校验，不通过不放行 | **P0-3** 4 步 Steps 向导 |
| 2 | 「部门还没定，岗位下拉里全是无关选项」 | 部门确定后岗位才可选，且只出现该部门下的岗位 | **P0-3** 部门 ↔ 岗位联动 |
| 3 | 「填到一半被叫走，回来得重填」 | 草稿自动持久化，再次进入时询问是否恢复 | **P0-3** 草稿自动保存 |
| 4 | 「交完不知道走到哪一步，得挨个部门打电话问」 | 流程进度可视化，节点留痕可追溯 | **P0-5** 审批流时间线 |
| 5 | 「主管找不到附件，让候选人重发一遍」 | 附件与流程绑定，待办消息里可直接进入 | **P0-6** 消息中心聚合待办 |

**验收标准**：新员工从打开表单到提交无需 HR 在旁口头指导；中途刷新浏览器不丢已填内容。

## R-002 · 员工花名册的日常维护

- **业务角色**：HR + 业务主管（研发主管）、财务
- **当前做法**：一份 1 万多行的 Excel 花名册，谁要谁拷一份，改完再发回去

| # | 痛点（业务原话） | 需求拆解（可验收的表述） | 落地 |
| --- | --- | --- | --- |
| 1 | 「上万行表格一滚就卡，筛选一下要等好几秒」 | 万级数据行保持 60fps 滚动；筛选/排序在客户端即时响应 | **P0-2** 全量 1 万条 + 虚拟滚动 |
| 2 | 「每个人的列偏好都不一样，每次都手动拖」 | 列显隐/顺序/宽度可配置，并记住每个人自己的设置 | **P0-2** 列设置 + 本地持久化 |
| 3 | 「调岗、离职要一行行点改，一上午就没了」 | 勾选多行后一次改状态 / 一次删除 / 一次导出 | **P0-8** 批量操作 + 实时计数 |
| 4 | 「工资、身份证号不该人人都看得到」 | 同一张表，不同角色看到不同字段；无权限字段走脱敏规则 | **P0-1** 字段级权限 + 脱敏 |
| 5 | 「导出的名单要能直接给外部，别出乱码」 | 导出 CSV 带 BOM（Excel 打开不乱码），且导出内容同样受字段权限约束 | **P0-8** CSV 导出 |

**验收标准**：财务登录后能看到金额与身份证列，普通员工看到的同名字段是脱敏值；导出的文件在 Excel 中打开中文不乱码。

> 这一条是**权限体系真正的试金石**：权限不能只挡菜单，必须一路管到「同一个单元格在不同人眼里内容不同」。

## R-003 · 季度预算与费用报销

- **业务角色**：财务 + 部门主管
- **当前做法**：预算 Excel 在群里来回传，报销走纸质单 + 签字

| # | 痛点（业务原话） | 需求拆解（可验收的表述） | 落地 |
| --- | --- | --- | --- |
| 1 | 「预算表在群里传了 6 个版本，不知道哪个是最终版」 | 数据以系统为准，图表按维度实时聚合 | **P0-4** 6 张 KPI / 趋势 / 部门 / 职位 / 雷达 / 排行卡 |
| 2 | 「想只看研发部的，得自己在一堆数字里挑」 | 点击部门柱 → 其余图表联动过滤 | **P0-4** 图表联动 |
| 3 | 「汇报要贴图、要 Excel、还要 PDF，每次重做」 | 一张卡支持 PNG / PDF / Excel 三种导出 | **P0-4 + P1-4** 多格式导出 |
| 4 | 「金额字段不该给所有人看」 | 金额类字段按角色控制可见性 | **P0-1** 字段级权限 |

**验收标准**：从「点开看板」到「拿到一份能直接贴进周报的 PDF」不超过 3 次点击。

## R-004 · 请假 / 出差 / 报销的审批

- **业务角色**：行政（流程发起与督办）、各级主管（审批人）
- **当前做法**：微信口头报备 + 事后补单，没有留痕

| # | 痛点（业务原话） | 需求拆解（可验收的表述） | 落地 |
| --- | --- | --- | --- |
| 1 | 「微信上说的，事后没人认」 | 每个节点有审批人、意见、时间，全程留痕 | **P0-5** 4 节点时间线（垂直 Steps） |
| 2 | 「审批人只想看该我办的，不想翻全量」 | 按「待我审批 / 已办结 / 我发起的」三视图切分 | **P0-5** 三 Tabs |
| 3 | 「点通过之前我想先看完整单据」 | 详情抽屉展示完整单据 + 流程轨迹，不跳页 | **P0-5** 详情 Drawer |
| 4 | 「不是所有角色都能批」 | 通过 / 驳回按钮按角色能力渲染，无权限不出现 | **P0-1 + P0-5** 按钮级权限 |

**验收标准**：主管在「待我审批」里能完成「看详情 → 点通过」全流程，且普通员工账号里根本不出现通过/驳回按钮。

## R-005 · 历史数据迁移与月度批量导入

- **业务角色**：HR（每月从考勤/招聘系统导出后入库）
- **当前做法**：先导出 Excel，再逐条录入系统

| # | 痛点（业务原话） | 需求拆解（可验收的表述） | 落地 |
| --- | --- | --- | --- |
| 1 | 「几千行一条条敲，敲一天」 | 拖拽上传 Excel / CSV，批量入库 | **P0-7** 导入页 |
| 2 | 「错了几行不知道错在哪」 | 逐行校验，错误行高亮并给出原因，可只导入正确行 | **P0-7 + excelValidate** 逐行校验 |
| 3 | 「几十万行的文件一上传，页面直接卡死」 | 解析放到 Web Worker，主线程不阻塞，页面保持可交互 | **P0-7** Web Worker 解析（30 万行实测不卡） |

**验收标准**：导入一个含错误行的文件，页面不停顿、不白屏，错误行被准确标出。

## 横向结论：5 条记录里抽出来的共性需求

上面 5 条是**业务功能**需求。把它们放一起看，会浮出一批**跨业务的技术性需求** —— 这部分往往才是决定系统好不好用的关键：

| 共性诉求 | 从哪来 | 落地 |
| --- | --- | --- |
| 不同角色看到的东西必须不同 | R-002 / R-003 / R-004 | **P0-1** 四级 RBAC：路由级 / 菜单级 / 按钮级 / 字段级 |
| 有外籍员工与海外分支 | R-001、组织信息 | **P1-1** i18n 中英双语 + 语言偏好持久化 |
| 用过的人都说「别一坏就白屏」 | 全流程 | **P1-2** ErrorBoundary + 路由 errorElement + 全局 onerror 兜底 |
| 「到底谁在用、慢在哪」说不清 | 全流程 | **P1-3** 埋点 SDK（PV/UV、点击、曝光、FCP/LCP/TTI） |
| 主管在外出差，用手机点审批 | R-004 | **P2-2** 窄屏 Sider 转 Drawer + 响应式 |
| 公司已有统一身份，不想再记一套密码 | 全员 | **P2-1** SSO（OAuth2 授权码流模拟） |
| 首屏要快、发版要稳 | 全流程 | **P2-3** 路由懒加载 + 分包；**P2-4** 单测 |

## 需求拆解的 3 步法（我实际用的流程）

1. **先记「现象」，不急着记「方案」**
   「填错要返工三次」是现象，「加个步骤条」是方案。**先把现象原样记下来**，方案晚一步再定 ——
   否则会直接把一个不成立的方案写进需求，返工在开发阶段。
2. **把现象翻译成「可验收的表述」**
   「表单要好用」无法验收；「分步校验，不通过不放行」可以验收。
   **凡是写不出验收标准的需求，多半是伪需求或还没想清楚。**
3. **标出上下游，再决定落在哪一层**
   同一个痛点往往牵动多层：「流程看不到进度」表面是审批页的事，
   实际要**审批流（P0-5）+ 消息中心（P0-6）**一起做才闭环。
   这一步能避免「页面做完了，业务还是没解决」。

## 优先级判断

| 优先级 | 判断依据 | 对应 |
| --- | --- | --- |
| **P0** | 不做业务就跑不通，或能力上限被卡死 | 权限、万级表格、表单、看板、审批、消息、导入、批量操作 |
| **P1** | 不做能用，但一上真实团队就出问题（乱码、白屏、没人知道错在哪） | i18n、错误边界、埋点、多格式导出、Mock 分层 |
| **P2** | 提升体验与工程成熟度，不阻塞业务 | SSO、移动端、打包优化、单测 |

**取舍原则**：能力上限类需求（表格扛不扛得住数据量、权限能不能管到字段）永远优先于视觉与体验类需求 ——
前者后期重构代价极高，后者可以随时迭代。

## 识别到、但主动不做或延后的需求

记录「不做什么」同样是调研的一部分：

| 需求 | 为什么先不做 |
| --- | --- |
| 多人实时协同编辑同一张表 | 需要后端 CRDT / OT 支持，纯前端演示无法体现价值，也非本岗位重点 |
| 拖拽式自定义报表设计器 | 工作量 2–3 周，收益低于把「权限 + 万级表格」这两项做深 |
| 组织架构树管理 | 与现有「部门」维度高度重叠，当前维度已够支撑业务 |
| 微前端拆分 | 当前是单体规模，为拆而拆只会增加复杂度 |
| 大屏可视化（数据大屏） | 与看板定位重叠，且大屏更偏展示、离业务操作更远 |

## 一句话总结

这份记录真正想说明的不是「我拜访了多少客户」，而是：
**我能把业务的一句抱怨，拆成一条可验收、有优先级、能落到具体代码位置的需求。**
